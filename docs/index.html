为什么需要它

存储已经接好了，缺的是一个会自己跑的调度层

AList / OpenList 解决了「怎么连上」，但没解决「什么时候同步、同步了什么、失败了怎么办」。这几件事以前只能靠手动复制或者自己写脚本。

以前

每次都要手动复制

相册满了、下载完了，都得自己想起来、自己点一遍，忘了就断档。

以前

脚本跑完不知道结果

命令行刷过一屏日志，哪些文件成功、哪些失败、传了多少，全靠翻记录。

现在

任务按点自己执行

按分钟间隔或 Cron 表达式定时跑，也能一键执行所有启用的任务。

现在

进度、失败、历史都留痕

实时看到扫描数、速度、剩余时间和每个文件的状态，失败项可以单独重试。

核心能力

一个任务能配的东西，比一条命令能记住的多

路径、规则、调度、并发、通知、历史，都收在同一个 Web 控制台里。

多源到多目标

一个任务里可以挂多个源目录和多个目标目录，不用为每条路径单独建任务。

  • 跨引擎组合
  • 本地 / 网盘 / 对象存储 / WebDAV

定时与手动并行

支持手动触发、按分钟间隔执行和标准 Cron 表达式，也能一键跑完所有启用任务。

  • interval · cron · manual
  • 可随时停止运行中的任务

精确过滤

Gitignore 风格的排除规则，加上最小 / 最大文件大小限制，缩略图和临时文件不用带走。

  • *.tmp · .DS_Store · @eaDir/
  • min / max size 阈值

实时进度

扫描数量、传输速度、预计剩余时间，以及已完成 / 运行中 / 等待 / 失败四类文件明细。

  • per-file 状态
  • 任务结束自动刷新

历史与重试

每次运行的开始时间、耗时和结果都留档，可以查看详情、只重试未完成项，或删除记录。

  • 自动重试次数可配
  • 历史保留天数可配

通知不吵人

内置 Server 酱、钉钉、企业微信、飞书 / Lark，也支持任意自定义 Webhook；没有文件变化时可以保持安静。

  • GET / POST / PUT
  • JSON 模板 + 自定义请求头
三种同步模式

先想清楚目标端「该留什么」，再选模式

这是配任务时最关键的一个选择，也是最容易搞反的地方，所以单独说明。

仅新增

add-only
源 A→A
源 B→B
—　旧 C 保留

只往目标端添加和更新，源端删掉的文件在目标端依然保留。

适合：照片、文档等只增不减的备份

全同步

full-sync
源 A→A
源 B→B
—　旧 C 清除

让目标端和源端保持一致，源端不存在的文件会在目标端被删除。

适合：影音库镜像、目标端要求严格一致

移动

move
源 A→A
源 B→B
源端腾空　全部就位

传输成功后从源端移除，用来腾空间或做一次性搬迁。

适合：下载目录归档、网盘之间迁移
怎么用起来

三步之后就不用再管了

从接入存储到看结果，是一条闭合的链路。

接入引擎

填 AList / OpenList 的地址和令牌，保存前会先验证连通性。可以同时管理多个实例，已保存的令牌不会再回显到界面上。

建一个任务

选好源目录和目标目录，挑同步模式，配排除规则、大小过滤、并发数和执行计划。可以先手动跑一次确认行为符合预期。

之后只看通知

任务按计划执行，有变化才推送。真出了问题就去历史记录里查详情、重试未完成项，不用整个任务重跑。

从添加引擎到收到通知，完整走一遍

不用先装一遍才知道流程长什么样。

和其他方案比

它不取代 rclone，而是补上可视化调度这一层

如果你习惯写脚本，rclone 依然很好用。OpenSync 面向的是想少维护、要界面、要留痕的那批人。

OpenSync 与 rclone、群晖 Cloud Sync、AList 内置复制的能力对比
能力 OpenSync rclone 群晖 Cloud Sync AList 内置复制
面向人群 飞牛 / NAS / Docker 用户 命令行与脚本用户 群晖用户 AList 用户
可视化任务管理 是 需自行套一层 UI 是 只能手动操作
AList / OpenList 集成 一等公民，多引擎管理 靠 WebDAV 或自行配置 不针对 原生，但没有调度
多源到多目标 单任务即可配置 可脚本实现 受产品限制 手动
实时逐文件进度 是 命令行输出 / 日志 产品界面 有限
历史里重试未完成项 是 可脚本实现 视产品而定 无
通知渠道 Webhook / Server 酱 / 钉钉 / 企业微信 / 飞书 可脚本实现 视产品而定 无
硬件与平台 amd64 / arm64 / armv7 跨平台二进制 仅群晖设备 跟随 AList 部署

对比基于各方案的公开定位与常见用法，具体能力可能随版本变化。

快速部署

一份 compose 文件，起来就能用

数据落在挂载出来的 ./data 目录，升级只需要拉新镜像重启。

terminal 
mkdir -p opensync && cd opensync
curl -O https://raw.githubusercontent.com/chenbin3625/OpenSync/main/docker-compose.yml
docker compose up -d
docker-compose.yml 
services:
  opensync:
    image: chenbin3625/opensync:latest
    container_name: opensync
    restart: unless-stopped
    ports:
      - "8023:8023"
    volumes:
      - ./data:/app/data
    tmpfs:
      - /tmp:mode=1777
    environment:
      TZ: Asia/Shanghai
      PUID: ${PUID:-1000}
      PGID: ${PGID:-1000}
      SQLITE_TMPDIR: /tmp
      TMPDIR: /tmp
      OPENSYNC_BIND: 0.0.0.0
      OPENSYNC_PORT: 8023
      GIN_MODE: release
1

打开控制台

浏览器访问 http://设备IP:8023/

2

创建管理员账号

首次启动按页面引导设置用户名和密码。

3

保存 24 位恢复密钥

只显示一次，忘记密码时用「用户名 + 恢复密钥」在网页上重置。

4

添加引擎，建第一个任务

填 AList / OpenList 地址和令牌，然后配置源、目标和同步模式。

恢复密钥也丢了的话，还有 CLI 兜底：docker compose exec opensync ./opensync reset-password --user admin。首次跑「全同步」或「移动」模式前，建议先在小目录上试一次。
